**1. B1R-1 and B1R-2: the custody fix's form.** Today `device()` parks the fresh reference after `_run` whenever `done is None or not done.saved` (`persistence.py` 460 to 461). That has two consequences:
- `_park` catches every failure of its insert and logs a fixed line (370 to 376), so a database that is unreachable for that statement loses the reference: B1R-1.
- An unknown outcome is read as "not saved", so after a lost commit acknowledgement a reference that a registration holds is also pending: B1R-2. The owner's later revoke, rotation or transfer is then refused by the pending discards' uniqueness, and B2's sweep would discard a token in use.

There are two forms of fix:
- **(a) The review's smallest.** `_park`'s `except` discards the reference through the store, with a second fixed log line if that fails too, and `_park` does not park a reference that a registration holds (one conditional insert). **Its residual:** after a lost commit acknowledgement with the database unreachable, the discard removes a token the committed registration holds. That registration stays `active` with a reference the store no longer has, until its next rotation. B1R-2's guard needs the database, so it cannot run in that case.
- **(b) A pending row written ahead, Codex's "recoverable handle" (the manager's recommendation):**
  1. After the store's `put` and before the command's transaction, the fresh reference's `PendingTokenDiscard` row is written in its own statement.
  2. If that insert fails, the store discards the reference at once and the command answers its error. Nothing has been committed, so nothing else holds the reference.
  3. The transaction that saves the reference on a registration deletes its pending row.
  4. After a known outcome that did not save it (a refusal, a replay, a conflict), the reference is discarded at once through `_discard`, as a retired one is, and its row removed. A failed discard leaves the row for B2's sweep.
  5. After an unknown outcome (`done is None`), the row is left alone. If the commit happened, the row went with it; if not, B2's sweep discards it.
  6. **A condition on D24:** B2's sweep discards a pending row only once it is older than a bound longer than any command's run (`Record.created_at`, which the table already has), and only if no registration holds its reference.
