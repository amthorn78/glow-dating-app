## Implemented checks

- Closed JSON Schema 2020-12 definitions for logical production intents and own/public/staff response projections; OpenAPI 3.1 component catalog references those definitions with no implemented paths or server. Existing development OpenAPI still describes only the real three GET routes.
- Deterministic types generated by exact-pinned json-schema-to-typescript 16.0.0; standalone validators generated by Ajv 8.20.0 with ajv-formats 3.0.1. The mobile decoder uses generated validators plus narrow array-key uniqueness checks, not handwritten text-length/trim logic. Generation check compares committed output bytes and catches schema/type/runtime drift.
- One committed **199-case** corpus is run by Python jsonschema and generated JavaScript. Coverage includes all named definitions; unknown/private/authority field rejection; Unicode astral scalar and combining-mark bounds; exact whitespace set, BOM and NEL; no normalization; lone-surrogate rejection; ASCII label final-newline cases; invalid/noncanonical timestamps, nested year-zero cases, leap seconds and invalid birth dates; duplicate IDs and preference dimensions; unknown-time preservation; restricted media/channel/export/deletion state projections; draft empty bio and explicit staff media target.
- F01–F20 have named executable acceptance methods against the test-only transition oracle. Actor/session/object/participant/case scope, stale version, missing policy, eligibility and active-match restrictions are exercised. Unknown transition/paid activation fails closed. Fixture contexts are trusted inputs for a design oracle; these tests do not authenticate anyone.

## Claim limits and next enforcement

This is an executable design baseline. No production HTTP handler, actual allauth release/configuration, durable auth session, PostgreSQL migration/constraint, concurrency, idempotency receipt durability, outbox/inbox persistence, live provider authorization, HDE contract/permission, signed native build or device acceptance is proven. The JSON Schema/runtime corpus is bounded shared evidence, not exhaustive proof across every JSON implementation or Unicode operation. Production payload size/rate limits and HTML-safe rendering still belong in real adapters/UI.

`transition_contract.py` is outside API runtime and is explicitly a test oracle. Real domain services must acquire current state under [trusted eligibility](../architecture/trusted-eligibility.md), use app UOW boundaries, and enforce projection-specific ownership/actor scope before returning data. Fixture system/provider/auth labels are not user-set roles. Idempotency records need a minimal immutable receipt and present-authorization recheck; old grant bytes are never blindly replayed. Pending A01/A07/A02/A05/A08/A06 dependencies stay explicit. Database/provider/native cases remain in [P11 deferred acceptance](p11-deferred-acceptance.md).
