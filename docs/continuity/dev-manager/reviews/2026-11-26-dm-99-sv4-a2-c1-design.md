## 3. Item 1 — A2R-1 and A2R-2: where the fix goes

### 3.1 The findings, checked in the code

- **The order in `send`** is as the review says. On the locked rows, `send` checks:
  1. the match's state (line 521), then the pair (523);
  2. the session's account (526);
  3. both accounts (528);
  4. the session's state, expiry and epoch (530 to 535);
  5. a block (544);
  6. the version (546);
  7. only then the profiles and consents (`_contact_state_checks`, 549).

  `send_error` answers `stale_version` for the version (`contract.py`, 169 and 170). Every session reason falls through to `error_for`'s `_UNAUTHENTICATED`, which is 401. `views.py` sets `WWW-Authenticate` only in `handle_exception`, the door, so a 401 from inside the send has no challenge.
- **A2R-1.** A wrong version answers 404 when the stop is above line 546, which covers an unmatch, a block, the other's suspension and the other's deletion. It answers 409 when the stop comes after it: a pause, a restriction, a withdrawn consent, or no cause at all. The reads serve a suspension and a pause alike, read-only, so the wrong version tells a member that the other is suspended. The contract's error table forbids that.
- **A2R-2.** The same split, by 404 against 401, for a session that ends between SV1's door and the send's session lock. Codex found it independently on `e28a5e2`. Its words: "the same ended session gets 404 `not_found` for an unmatched conversation or suspended partner, versus 401 `unauthenticated` for a paused/restricted partner".
- **Both are defects at a security boundary** (what a member learns of the other's state), in A2's own route layer. So A2R-2 is a correction, not a carry. It falls in the class A2's review prompt names ("what a member learns of … a refused send's cause"), and the fix is a few lines in the same function. That rules out (c).

### 3.2 Why (a), not (b)

- **(a) does not depend on the order.** Whatever `send` refuses after its locks, among those reasons, answers one code. A later change to the adapter's order cannot reopen it, and (b) can.
- **(a) changes nothing proven.** `send` stays as P06.DB's 5.6 and A1 left it: `ReciprocalWriterTests`' digests hold, and the ordering suite's expectations stay as they are. D8 says the route calls "`glow_chat`'s `send` unchanged", so (b) would also change the brief's design.
- **What (a) gives up is invisible to a correct client.** Under D6 an active match's version is 1, and it changes only when contact ends, after which the match check answers first. Only a client that sends a version the match never had loses `stale_version`. The mobile client's `stale` failure is the history cursor's reset (`store.ts`, line 256); its send path never relies on it. The mobile fixture adapter still answers `stale_version` for a wrong send version (`fixture-adapter.ts`, line 276), which is a difference for AC3 to take up when it replaces the fixtures (carried, section 6).
- **A session missing before the checks stays 401,** and rightly. `session_missing` (the read before the locks) and `accountsession_missing` (raised by `_lock` itself, before any check) are both found before any cause is checked, so they cannot split causes.

### 3.3 AK1 — the reads have the same split

The history read and the read cursor go through `reads.py`'s `_authorize` (lines 512, 611 and 766), and it has the send's shape:

- the match's state, then the accounts (the other `active` or `suspended`);
- then the session's state, expiry and epoch;
- then a block and the causes (`readable`, which refuses a hidden cause as `conversation_hidden`).

`read_error` maps every session reason to 401 through `error_for`. Suppose a member's session ends after SV1's door and before the read's session lock. An unmatch, a block or the other's deletion then answers 404, while a cause the console has published `hidden` answers 401. With a valid session both answer 404, the same, as D5 requires ("one refusal for every hidden cause, never naming which"). So the race tells a hidden cause from an ended contact.

- **At launch nothing is exposed:** every cause reads `read_only`.
- **But the console can publish `hidden` at any time without a code change.** OD-60 makes each cause's setting editable, and making a cause less readable needs no new consent. So the split would open in production with no code change.
- **The fix is the same mapping in `read_error`,** for the conversation's own reads only. The list refuses as a whole and names no conversation, so its 401 stays.

This also makes A2R-11 moot for the send, the history and the cursor. A2R-11 stays carried for the list.
