## Code Review Rules

- Governing Markdown (`AGENTS.md` or `CLAUDE.md` at any level, `docs/pf-canon/`, the manager workflow, the Dev Manager charter and the CI policy) skips code review as ordinary documentation, but the Dev Manager reads it, at a named commit, before its PR merges. The Dev Manager also reads any prompt that authorizes credential use or live provider actions before Nathan runs it. See `docs/planning/dev-manager.md`.

- Before commissioning or performing a review, classify the complete PR diff with the **trusted base revision** of `scripts/change_scope.py`, extracted outside the candidate worktree and run with `python3 -I` and `--base <base-sha> --head <head-sha> --merge-base`. Do not execute or import candidate code/tests to decide whether it needs review. A missing trusted policy, unavailable comparison or ambiguous classification (including more than one merge base) requires full review. Per Nathan's direction of 24 September 2026, a change made only of regular Markdown files (documentation, instructions, plans, handoffs, prompts and canon) is ordinary documentation, except any path under a `.claude/` directory. Claude Code skills, commands, agents and rules there can carry commands and permissions, so they stay full scope. Ordinary documentation runs neither application CI nor code/security review. Any script, code, configuration, workflow, environment template or other non-Markdown file, and any symlink or executable file, makes the whole change full scope. For an `ordinary-docs-only` result, do not start code/security review or application build/test jobs. If an external trigger already started you, stop after classification and report **Review not required: ordinary documentation only**. Do not inspect application code or create review findings for that exempt change.
- Preserve fixture-only runtime guards, private projections, eligibility freshness and the protected HDE boundary. A planned provider slot is not an active secret loader or a verified permission mechanism.
- Follow `docs/operations/ci-and-branch-policy.md`. Classify the full PR: Markdown-only changes outside any `.claude/` directory skip application checks and review requests. Code, scripts, mixed changes, workflow/configuration and environment templates require normal checks and exact-head review evidence. In a full-scope review, never suppress a finding merely because its file ends in `.md`.
- CI routing is not an independent security boundary: PR-controlled workflow YAML can change its classifier invocation, job conditions or gate. For workflow or classification-policy changes, the manager must independently classify with the pre-change policy, inspect the complete workflow diff and actual job steps/results, and require full checks before merge. A green or skipped candidate check alone is insufficient. Do not infer immutable enforcement from the trusted script; branch/account enforcement remains limited as documented.
- Preserve failures and claim limits. Check the current head after corrections; earlier-head reviews do not certify later changes.
