## Code Review Rules

- Before commissioning or performing a review, classify the complete PR diff with the **trusted base revision** of `scripts/change_scope.py`, extracted outside the candidate worktree and run with `python3 -I` and `--base <base-sha> --head <head-sha> --merge-base`. Do not execute or import candidate code/tests to decide whether it needs review. A missing trusted policy, unavailable comparison or ambiguous classification requires full review. The exemption covers only the policy's inert evidence/provenance allowlist; operational commands, architecture, READMEs, plans and other instruction surfaces are full scope. For an `ordinary-docs-only` result, do not start code/security review or application build/test jobs. If an external trigger already started you, stop after classification and report **Review not required: ordinary documentation only**. Do not inspect application code or create review findings for that exempt change.
- Preserve fixture-only runtime guards, private projections, eligibility freshness and the protected HDE boundary. A planned provider slot is not an active secret loader or a verified permission mechanism.
- Follow `docs/operations/ci-and-branch-policy.md`. Classify the full PR: ordinary documentation skips application checks and review requests; code, mixed changes, agent instructions, all persistent planning (including implementation briefs), PF canon, workflow/configuration and environment templates require normal checks and exact-head review evidence. Never suppress a finding merely because its file ends in `.md`.
- CI routing is not an independent security boundary: PR-controlled workflow YAML can change its classifier invocation, job conditions or gate. For workflow/policy/instruction changes, the manager must independently classify with the pre-change policy, inspect the complete workflow diff and actual job steps/results, and require full checks before merge. A green or skipped candidate check alone is insufficient. Do not infer immutable enforcement from the trusted script; branch/account enforcement remains limited as documented.
- Preserve failures and claim limits. Check the current head after corrections; earlier-head reviews do not certify later changes.
